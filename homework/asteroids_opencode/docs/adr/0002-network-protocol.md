# ADR 0002: 网络协议设计

## 状态
Proposed

## 上下文
项目需要实现在线多人功能，当前WebSocket实现过于简单，存在延迟和同步问题。

## 决策
实现客户端预测 + 服务器重播机制。

## 理由
- **减少感知延迟**：客户端预测让操作立即响应
- **保证一致性**：服务器权威控制游戏状态
- **处理网络抖动**：重播机制纠正预测误差
- **确定性保证**：固定时间步长确保状态一致

## 技术方案
- **客户端预测**：输入队列 + 本地状态快照
- **服务器重播**：接收服务器状态，校正本地预测
- **插值**：平滑状态过渡，减少跳跃
- **压缩**：使用bincode替代JSON减少带宽

## 协议细节
- **输入序列号**：每个输入包带唯一ID
- **状态快照**：定期发送完整游戏状态
- **Delta压缩**：只发送状态变化
- **时间同步**：NTP-like算法同步客户端时钟

## 备选方案
- **纯服务器权威**：简单但延迟高
- **乐观重播**：复杂但体验最好
- **Lockstep**：确定性但网络要求高

## 后果
- **正面**：流畅的多人体验，低延迟操作
- **负面**：实现复杂度高，调试困难
- **风险**：网络条件差时体验下降

## 实施计划
1. 实现基础输入同步
2. 添加客户端预测缓冲区
3. 实现服务器重播机制
4. 添加状态插值和平滑
5. 性能优化和压缩

## 验收标准
- 网络延迟<100ms时无明显操作延迟
- 丢包率<5%时状态保持同步
- CPU使用增加不超过20%
- 带宽使用<50KB/s per client
