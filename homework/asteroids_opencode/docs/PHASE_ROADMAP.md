## 待实施

### Phase 4: 延迟补偿与命中检测优化 🔄

**目标**: 改进子弹命中检测，考虑网络延迟

**子任务**:
| 任务 | 可并行 | 关键文件 |
|------|--------|----------|
| 4A: 子弹发射时间戳携带 | ✅ | `src/network.rs`, `src/bullet.rs` |
| 4B: 服务器回溯命中检测 | ✅ | `server/src/main.rs` |
| 4C: 客户端命中提示(乐观反馈) | ✅ | `src/effects.rs`, `src/ui.rs` |
| 4D: 命中检测调试视图 | ✅ | `src/ui.rs` |
| 4E: 延迟容忍度测试 | ❌ | `tests/` |

**潜在风险**:
- 回溯窗口过大导致性能下降
- 时间同步不准导致误判
- 客户端与服务器命中结果不一致造成"鬼子弹"

**验收标准**:
- [ ] 不同 RTT (0-200ms) 下命中结果一致
- [ ] 无明显假命中/漏判
- [ ] 调试视图可显示回溯窗口
- [ ] 测试覆盖典型 RTT/抖动场景

---

### Phase 5: 网络健壮性与断线重连

**目标**: 处理网络断开、超时、重连逻辑

**子任务**:
| 任务 | 可并行 | 关键文件 |
|------|--------|----------|
| 5A: 心跳/Ping-Pong 机制 | ✅ | `src/network.rs`, `server/src/main.rs` |
| 5B: 客户端连接状态机 | ✅ | `src/network.rs` |
| 5C: 指数退避重连 | ❌ | `src/network.rs` |
| 5D: 服务器会话保活/清理 | ✅ | `server/src/main.rs` |
| 5E: UI断线/重连提示 | ✅ | `src/ui.rs` |
| 5F: 重连状态恢复 | ❌ | `src/network.rs`, `server/src/main.rs` |

**潜在风险**:
- 误判掉线导致频繁重连
- 状态恢复不全导致玩家丢分/位置错乱
- 重连风暴压垮服务器

**验收标准**:
- [ ] 断网后能在限定重试内恢复
- [ ] UI 清晰显示网络状态
- [ ] 无僵尸会话泄漏
- [ ] 重连后状态正确恢复

## 优先级

1. **高**: Phase 4, 5 (核心网络体验)
2. **中**: Phase 6, 7 (安全性和跨平台)
3. **低**: Phase 8 (优化和规模化)
